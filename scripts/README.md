# scripts/ — Medium publishing pipeline

Two scripts, two phases of the publish workflow:

| Script | What it does |
|---|---|
| `compile_assets.py` | Renders `assets/cover.py` + `assets/diagram-NN.{mmd,py}` per article into PNG files. |
| `to_medium.py` | Extracts the article body, converts markdown → HTML, embeds the cover and diagram PNGs at the right places, and produces `medium-paste.html`. |

Run them in order: `compile_assets.py` first, then `to_medium.py`. For convenience:

```bash
python3 scripts/compile_assets.py all && python3 scripts/to_medium.py all
```

---

## scripts/compile_assets.py

Looks in `output/<slug>/assets/` for source files and renders them:

- `cover.py` (Python script using `cover_template.make_cover`) → `cover.png`
- `diagram-NN.mmd` (Mermaid source) → `diagram-NN.png` via `mmdc`
- `diagram-NN.py` (Python script writing a PNG via matplotlib or Pillow) → `diagram-NN.png`

```bash
python3 scripts/compile_assets.py 1     # one article
python3 scripts/compile_assets.py all   # all 6
```

Requirements: `pip3 install Pillow matplotlib` and `npm install -g @mermaid-js/mermaid-cli`.

The file naming for `diagram-NN` must match the ORDER of `[Insert Diagram: ...]` markers in the article body. See `agents/graphic-designer.md` for the full spec.

## scripts/to_medium.py — paste articles into Medium

Same idea as `markdown-to-medium.surge.sh`, but local and tied to your output.

## One-time setup

You need one of:

- **pandoc** (preferred — cleaner output): `brew install pandoc`
- **or** Python markdown library: `pip3 install markdown`

The script prefers pandoc and falls back to the Python library if pandoc isn't installed.

## Workflow A — Browser (3 keystrokes, identical to surge.sh)

```bash
python3 scripts/to_medium.py 1
```

This opens `output/01-prompt-caching-vs-semantic-caching/medium-paste.html` in your default browser. Then:

1. **Cmd+A** in the browser tab
2. **Cmd+C**
3. Open Medium, click in the editor body, **Cmd+V**

The script also prints the **Title** and **Subtitle** to the terminal — paste those into Medium's separate Title and Subtitle fields (those don't come along with the body paste).

## Workflow B — Direct clipboard (single Cmd+V)

```bash
python3 scripts/to_medium.py 1 --copy
```

This copies the rendered article as rich text directly to your macOS clipboard. Open Medium, click in the editor body, **Cmd+V**. Done. Browser doesn't open.

Same terminal output for Title and Subtitle still applies.

## Render all 6 at once

```bash
python3 scripts/to_medium.py all
```

Writes `medium-paste.html` to each of the 6 article folders. Useful as a batch pre-generate step before your publish window.

## Flags

| Flag | Effect |
|---|---|
| `--copy` | Copy rich text directly to clipboard; skip browser. |
| `--no-open` | Generate the HTML file but don't open the browser. Useful for `all`. |

## Troubleshooting

- **"Need pandoc OR pip3 install markdown"** — install one of the two. Pandoc is preferred.
- **Title shows empty** — the script reads the title from the `# H1` line in the article body. If you edited that line out, it won't find it. Re-add the H1 line.
- **Clipboard copy says "failed, falling back to browser"** — `textutil` or `pbcopy` couldn't run. This happens on non-macOS systems. The script falls back to the browser flow automatically.
- **Paste into Medium drops some formatting** — this happens occasionally with code blocks containing certain Unicode characters. If a code block looks off, re-copy from the browser instead of using `--copy` (browser-clipboard tends to be more reliable than RTF-clipboard for code blocks).
